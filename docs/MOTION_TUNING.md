# 「動作太大時不補幀」使用與調整指南

> 這份文件說明進階設定裡的「**動作太大時不補幀**」：它在做什麼、在 App 裡怎麼用，
> 以及怎麼用終端機的輔助工具，找出最適合你影片的設定，並對應回 App 的設定。
>
> ⚠️ 目前三段的門檻數字是開發者先估的，**還沒用真的影片驗證過**。照下面的步驟調整幾支影片後，就會越來越準。

---

## 1. 這個功能在做什麼

AI 補幀是「看前後兩張畫面，猜中間應該長什麼樣子」。遇到**動得很猛**的地方，AI 容易猜錯，
在移動的東西輪廓周圍產生像水波一樣的扭曲（波紋、鋸齒、重影）。常見的情況：

- 離鏡頭很近、動作又快（揮手、甩頭髮、跳舞）
- 東西互相遮住，又露出來
- 原影片有動態模糊，或畫質偏低

打開這個選項後，轉檔時每兩張原始畫面會先量一個「**動作分數**」：

| 動作分數 | 處理方式 | 看起來 |
|---|---|---|
| 沒超過門檻 | 照常補幀 | 順 |
| 超過門檻 | **不補幀**，直接重複前一張原始畫面 | 那一瞬間回到原本 30 FPS 的感覺，但不會有 AI 猜錯的波紋 |

一支影片裡通常只有少數幾個瞬間會被跳過，其他地方照常補幀。

**代價**：

- 被跳過的那幾瞬間，順暢度會回到原本的樣子。
- 轉檔會比較慢，因為要多做一次動作追蹤。慢多少，安裝時的自我測試會在「速度參考」列出來。
- 不保證能完全消除波紋：有些波紋不是動作太大造成的，例如壓縮造成的色帶，或細密的條紋。

---

## 2. 在 App 裡怎麼用

1. 打開 FrameBooster，點「**進階設定**」展開。
2. 勾選「**動作太大時不補幀**」。
3. 在旁邊選一段：

   | App 的選項 | 意思 | 適合 |
   |---|---|---|
   | **少跳過** | 只跳過動作最猛的地方 | 想要最順，可以接受一點波紋 |
   | **適中**（預設） | 介於兩者之間 | 先從這個開始試 |
   | **多跳過** | 動作稍大就跳過 | 最在意波紋，可以接受比較多瞬間不那麼順 |

4. 勾選要轉的影片，按「開始轉檔」。設定是在按下的那一刻套用的。
5. 轉完後，那一列會多一行，例如「**有 23 處動作太大，未補幀**」。

> 這個設定**不會被記住**：每次打開 App 都是關閉的，避免忘記它開著。

**怎麼選**：先用「適中」轉一次。

- 波紋還是很明顯 → 改「多跳過」再轉一次。轉完的影片可以再勾選重轉，新檔會另外存。
- 覺得有些地方變得不夠順 → 改「少跳過」。
- 三段都不理想 → 照第 4 節用輔助工具找出適合的數字。

---

## 3. 「動作分數」是什麼

**動作分數＝畫面裡動得最猛的那一小塊（約 1% 的面積），在兩張原始畫面之間移動了「畫面長邊的百分之幾」。**

- 例如分數 5：那一小塊移動了畫面長邊的 5%。直式 1080p 影片的長邊是 1920 像素，大約就是 96 像素。
- 會先**扣掉整個畫面一起移動**的部分，例如手持晃動、鏡頭平移，因為 AI 很擅長處理整體移動。真正容易出錯的，是「某個東西自己動得很猛」。
- 分數和影片解析度無關：720p 和 4K 的同一個動作，分數差不多。

**三段對應的門檻數字**（分數**超過**門檻就不補幀；門檻越低，跳過的地方越多）：

| App 的選項 | 門檻 | 指令寫法（兩種都可以） |
|---|---|---|
| 少跳過 | **8.0** | `--skip-motion less` 或 `--motion-threshold 8` |
| 適中 | **5.0** | `--skip-motion normal` 或 `--motion-threshold 5` |
| 多跳過 | **3.0** | `--skip-motion more` 或 `--motion-threshold 3` |

門檻的修改紀錄見[第 7 節](#7-門檻修改紀錄)。

## 4. 用輔助工具調整（終端機）

輔助工具在終端機裡執行。不用會寫程式，照著複製貼上就可以。

### 準備

1. 先確認已經雙擊過 `安裝.command`（它會編譯出命令列工具 `build/frame-booster`）。
2. 打開「終端機」，貼上這一行並按 Enter，切換到專案資料夾：

   ```bash
   cd ~/Desktop/frame-booster
   ```

3. 下面的指令裡，`影片路徑` 要換成你的影片。最簡單的方法是：先打好指令前面的部分（後面留一個空格），再把影片從 Finder **拖進終端機視窗**，路徑就會自動填好。

### 步驟 1：產生動作分析報告（只分析、不轉檔）

```bash
build/frame-booster --analyze 影片路徑
```

終端機會印出報告。下面的數字只是**示意**，你的影片會不一樣：

```
=== 動作分析：（影片檔名） ===
影片長度 32.0 秒、原始約 30 FPS；分析花了 6.1 秒

門檻對照（分數超過門檻的地方不補幀）：
  少跳過：門檻 8.0 → 會跳過 1.2% 的畫面間隔
  適中：門檻 5.0 → 會跳過 4.8% 的畫面間隔
  多跳過：門檻 3.0 → 會跳過 15.3% 的畫面間隔
分數分布：中間值 1.4、90% 的地方在 3.6 以下、最大 11.2

時間      動作分數   少跳過  適中  多跳過
0:00.0      1.2      ·     ·     ·
0:00.5      3.8      ·     ·     ✂
0:01.0      9.5      ✂     ✂     ✂
...
（✂＝這一段會被跳過、不補幀；·＝照常補幀）
表格已存成：（影片所在的資料夾）/影片名_動作分析.csv
```

怎麼看：

- 每 0.5 秒一行，「動作分數」是那半秒裡最大的分數。
- 後面三欄表示用 App 的三段時，那半秒會不會被跳過（✂）。
- 同樣的內容也存成表格檔（`影片名_動作分析.csv`，在原影片旁邊），可以用 Numbers 或 Excel 打開。原影片不會被改動。

### 步驟 2：找出「有波紋」的時間點

用 QuickTime Player 播放**用一般設定轉好的影片**（沒開這個選項的版本），記下哪幾秒有明顯的波紋，例如：

```
有波紋：0:01、0:12～0:13、0:35
沒有波紋但動作很多：0:20～0:25
```

### 步驟 3：對照分數，挑一個門檻

把步驟 2 的時間點和步驟 1 的報告對照：

- **有波紋的時段**分數大多是多少？例如都在 6 以上。
- **沒有波紋的時段**分數大多是多少？例如大多在 4 以下。
- 門檻就挑在兩者之間，例如 **5**。

如果有波紋的時段分數反而很低，表示那裡的波紋可能**不是動作太大造成的**，這個功能幫不上忙。可能是壓縮的色帶或細密花紋，見 README 的常見問題。

### 步驟 4：用自訂門檻試轉「標記版」

```bash
build/frame-booster 影片路徑 --fps 60 --motion-threshold 5 --mark-skipped
```

- `--fps 60`：換成你平常用的目標幀率。
- `--motion-threshold 5`：換成步驟 3 挑的數字。
- `--mark-skipped`：產生**標記版**，被跳過補幀的畫面會在**四個角落出現紅色小方塊**。四個角落都畫，是因為直拍影片播放時會旋轉。
- 轉好的檔名多了「_標記」，例如 `原檔名_60fps_標記.mov`，放在原影片旁邊。終端機最後也會顯示「動作太大、沒補幀：幾處」。

播放標記版，確認兩件事：

1. 原本有波紋的地方，有沒有出現紅色小方塊、波紋是不是不見了？
2. 紅色小方塊有沒有出現在**不需要跳過**的地方（那裡本來就沒波紋）？

- 波紋還在 → 門檻**調低**一點（例如 5 → 4），再試一次。
- 太多不必要的紅方塊 → 門檻**調高**一點（例如 5 → 6）。

> 標記版只是用來調整的，**不是拿來看的成品**。找到合適的門檻後，用 App（或不加 `--mark-skipped` 的指令）再轉一次正式版。

### 步驟 5：對應回 App 的設定

| 你試出來的門檻 | 在 App 裡怎麼做 |
|---|---|
| 接近 8 | 選「少跳過」 |
| 接近 5 | 選「適中」 |
| 接近 3 | 選「多跳過」 |
| 和三段都差很多（例如 6.5 或 2） | ① 暫時用指令轉正式版：`build/frame-booster 影片路徑 --fps 60 --motion-threshold 6.5`（不加 `--mark-skipped`）；② 把結果告訴開發者（見下一節），一起決定要不要調整 App 三段的數字 |

App 只有三段，是為了讓畫面保持簡單。調整幾支影片後，如果發現你最常用的數字和某一段不一樣，就把那一段的數字改掉。

## 5. 需要開發者（Claude）幫忙時，要提供什麼

**只需要數字和時間點，不需要影片，也不需要截圖。** 分析和轉檔都在你的 Mac 上進行，影片不會離開你的電腦。

請提供：

1. **動作分析報告的數字**：可以直接複製終端機的報告，或打開 CSV 複製內容。
   報告第一行有影片檔名，不想透露可以先刪掉那一行。
2. **有波紋／沒波紋的時間點**（步驟 2 記下的）。
3. **試過的門檻和感覺**，例如「門檻 5：0:12 的波紋不見了，但 0:20 多了很多不必要的紅方塊」。
4. **影片的基本條件**：解析度、長度、大概是什麼來源（手機拍的、網站下載的）、目標幀率。

開發者會根據這些數字，建議門檻或調整 App 三段的數字。這些數字和時間點**不會**放進專案、GitHub 或任何紀錄；專案裡只會記錄「門檻改成多少」（第 7 節）。

## 6. 常見問題

**Q：打開之後，轉檔會變慢多少？**
A：要多做一次動作追蹤，所以會比較慢。為了快，動作追蹤時會先把畫面縮小（長邊 640 像素）再分析。實際慢多少，安裝時自我測試的「速度參考」會列出「120 FPS・精細＋動作太大時不補幀」的時間，可以和「120 FPS・精細」比較。關閉這個選項時，速度和原本完全一樣。

**Q：被跳過的地方看起來會頓一下嗎？**
A：可能會稍微感覺到順暢度變化，因為那一瞬間回到原本 30 FPS。通常那裡本來就是動作很快、很模糊的地方，不容易察覺，但每支影片不一樣。

**Q：一般轉檔也會出現紅色小方塊嗎？**
A：不會。只有命令列加了 `--mark-skipped` 的標記版才會有，App 轉出來的影片不會有。

**Q：開了「多跳過」，波紋還是在？**
A：照第 4 節看報告。如果有波紋的地方分數很低，表示那裡的波紋不是動作太大造成的，這個功能幫不上忙。

**Q：報告的分數都是 0，或都非常小？**
A：可能是 Apple 動作追蹤輸出的單位和預期不同。請把報告給開發者看，這需要修改程式。

## 8. 給開發者的技術說明

- 程式在 `Sources/Motion.swift`：
  - 三段的門檻：`MotionSkipLevel.threshold`。**改數字時要同步更新這份文件的第 3 節和第 7 節。**
  - 動作分數：`MotionAnalyzer`
  - 報告：`MotionReport`
  - 紅色小方塊：`SkipMarker`
- 動作追蹤用 Apple 的 `VTOpticalFlowConfiguration`／`VTOpticalFlowParameters`（VideoToolbox，macOS 15.4 起），在獨立的 `VTFrameProcessor` 工作階段執行。畫面先縮小（長邊 640）再分析。
- 分數的算法：
  1. 每隔一格取樣「往前」的光流（每個像素的 x、y 移動量）。
  2. x、y 各取中位數，當成整體移動，先扣掉。
  3. 剩下的移動距離取第 99 百分位。
  4. 除以分析畫面的長邊 × 100。
  - 這裡假設光流的單位是「分析畫面的像素」；如果實測分數異常，例如全部接近 0，要先檢查這一點。
- 補幀端：`FrameGenerator` 在每一組相鄰原始畫面要補幀前先量分數，超過門檻就重複前一張原始畫面，標記版則用畫了紅方塊的複本。補幀本身仍用 `usePrecomputedFlow: false`，沒有共用這份光流。日後若轉檔太慢，可以考慮把光流直接傳給補幀引擎（`usePrecomputedFlow: true`），避免算兩次；但補幀需要原尺寸的光流，目前為了快是縮小後才分析，要先評估哪一種比較快。
- 自我測試（`scripts/selftest.sh`）會試用這個功能、標記版和分析報告，**只報告結果、不影響安裝**。
